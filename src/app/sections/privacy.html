The visit count

The web app and this page count visits

The app has no server of its own, so the web build uses GoatCounter — the same counter that runs on the author’s site. It exists so “is anybody using this?” has an answer without DeepWork running a backend.

    @for (line of counter; track line) {
  • ✓ {{ line }}
    • }

This page counts its own visits the same way, on its own GoatCounter site, deepwork.goatcounter.com, so the two never mix in a dashboard. It sends the address, the title, the referring site and the screen width; it sets no cookie, GoatCounter stores no IP address, and no third-party script is loaded to make the request — the page sends the beacon itself. A browser that asks not to be tracked is not counted, and the Site stats button in the footer only asks GoatCounter for the totals back.

Five log files you can actually open

When something goes wrong on a machine nobody can sit in front of, the app has already written down what it was doing. Settings has one button that opens the folder and another that copies the last 300 lines with the environment they happened in.

    @for (line of logs; track line) {
  • {{ line }}
    • }

Each file rolls over at 512 KB, keeps its five most recent archives, and can never grow past roughly 15 MB. Identical lines inside two seconds are folded into one with a count, so a repeating fault cannot flood the file.

Offline is the normal case

The fonts travel with the app, the alert tones are synthesised rather than downloaded, and the database is a file on your disk. Nothing in the app needs the network to look like itself or to keep your records.
